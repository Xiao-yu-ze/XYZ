## 二、用户确认过的参数（以这些为准，不要另猜）

1. **节点间隔 100ms，识别间隔/超时 100ms**。进关判定必须快 —— boss 关喂豆打断靠它抢时间，
   用户原话："延迟越快越好，50~200ms 之间"。
2. **进关判定：普通关与 boss 关相同**，ROI `[700,1004,40,40]`，
   色域 `[148,213,8]~[168,233,28]`（我们取中点 `#9AD216`，容差 85%）。
3. **开始战斗**：三个玩法都用 `xinta/开始战斗.png`；**认不出再退 OCR**。
   （当前实现是 OCR「开始战斗」，模板图还没拷进 assets。）
4. **结算只有「继续挑战」一种文字**，boss 关也一样。
5. **补给分类不要硬编码坐标** —— 用「点击文字」直接点识别到的词
   （全部植物 / 橙色植物 / 蓝色植物 / 紫色植物 / 神器）。
6. **编队切换**：右下角出现「开始战斗」时才能切；6 个编队按钮坐标**待用户给**。
7. **boss 关 = 关卡 % 5 == 0**，是补给之后进的那一关；选卡同普通关，只是关内链不同
   → 每个阶段要两套链（普通 / boss）。
8. **循环 → 收尾 的判定由程序内建**，不给用户配（照 MAA：战斗链尾判「结算」）。
9. **进关后不自动点加速** —— 表上本来就有「加速」动作，用户自己放。
10. MAA 那套 ROI 是 **1920×1080** 基准，我们虚拟屏 1280×720，统一 ×2/3。
