# 方案 C：识别链验证

## 这条链要回答什么问题

**模板匹配和 OCR 在真机上到底准不准。**

这是整个自动化的地基。作业集（`jobs/*.json`）和 pipeline 都是靠识别驱动的，
如果识别层本身就会飘，那么把 MaaPVZ 的引擎（`JobSetLoad` / `JobSetFight` /
`BatchSwipe`，约 5000 行 Python）移植成 Kotlin 就是白费力气。

所以先不移植引擎，只跑**一条纯声明式的识别链**，用真实分数说话。

## 链路是什么

```
无尽挑战_点击竞技          TemplateMatch  create_yard/竞技.png
  └→ 无尽挑战_点击无尽挑战   TemplateMatch  Endless/无尽挑战.png
       └→ 无尽挑战_点击开始挑战  OCR  开始挑战 / 继续挑战   roi=[790,531,231,97]
```

三个节点覆盖**三种识别通道**：单模板匹配、多模板、OCR + 紧 ROI。
全部是声明式的，**不含任何 Custom 动作**，所以不需要移植引擎就能跑。

> 为什么从中段切入：入口 `无尽挑战_前置检查_ref` 之后第一步就是
> `JobSetLoad`（Custom 动作），我们跑不了。所以从它之后的第一个纯识别节点开始。

## 怎么用

1. 同步素材（必须先做，否则 pipeline 是空的）：

   ```powershell
   .\tools\sync-maapvz-assets.ps1 -MaaPvzRoot "C:\Users\29374\Desktop\MaaPVZ-win-x86_64-v0.5.4-ci.261001-670c36e"
   ```

2. 编译安装：

   ```powershell
   .\gradlew.bat :app:assembleDebug
   ```

3. 手机上打开 **PVZ2 主界面**（能看到「竞技」按钮的那一屏）。

4. 点 **`① 识别链·干跑`** —— 只识别不点击。

5. 看日志（标签 `PipelineRunner` / `NodeGraph` / `Recognizer` / `OcrEngine`）：

   ```
   adb logcat -s PipelineRunner:I NodeGraph:I Recognizer:I OcrEngine:I
   ```

6. 确认无误后，再点 **`② 识别链·实跑`**（会真的点击）。

## 日志怎么看

**干跑**会打印每一帧每个候选节点的分数与决策：

```
PipelineRunner: pipeline 载入 66 个节点，入口 [无尽挑战_点击竞技]，dryRun=true
NodeGraph: 从节点 [无尽挑战_点击竞技] 开始执行
NodeGraph: [干跑] 点击 [无尽挑战_点击竞技] 命中分数=0.9871 逻辑(640,360) -> 本该点屏幕(640,360)（未执行）
```

判读标准：

| 现象 | 含义 |
|---|---|
| 分数 **≥0.90** | 极强，模板、缩放、坐标全对 |
| 分数 0.80~0.90 | 可用，但建议检查模板裁剪是否贴边 |
| 分数 0.70~0.80 | 偏弱，容易误判，建议重裁模板 |
| 分数 <0.70 | 模板/缩放/ROI 有一处不对 |
| `未命中` 且分数很低 | 多半是**人没停在正确的界面**，不一定是 bug |

**OCR** 的日志会打印识别到的原始文本，这是判断 OCR 是否可用的唯一依据：

```
OcrEngine: 已就绪：[x] / [x]
NodeGraph: [干跑] 点击 [无尽挑战_点击开始挑战] 命中分数=0.9xxx 文本=继续挑战
```

如果 `文本=` 后面是乱码或空，说明 CTC 字典或类别对齐有问题（见下方「已知风险」）。

## 已知风险 / 未验证项

1. **OCR 从未在真机跑过。** `OcrEngine` 是手写的 ONNX 推理，以下三处都可能出错：
   - `keys.txt` 是 CRLF，代码里已剥 `\r`，但**字典类别数对齐**（18385 vs 18383）没实测过；
   - CTC 解码的 blank/重复字符处理；
   - PP-OCR 的 NCHW 布局与归一化参数。
   如果 OCR 全灭但模板匹配正常，问题一定在这三处。

2. **`pre_delay`/`post_delay` 未生效验证。** `无尽挑战_点击开始挑战` 之后
   指向 `无尽挑战_自动计数`（需要 `JobSetAutoCount` 这个 Custom 动作），
   我们没有实现 —— 走到那里会看到「未注册的自定义动作」然后按失败处理。
   **这是预期行为**，说明链已经跑通到了引擎的边界。

3. **屏幕必须是 1280×720 或等比。** 坐标基准是 720p，`ScreenAdapter` 会做等比换算，
   但 MaaPVZ 的 ROI 是按 720p 定死的，非常规比例下 ROI 可能对不上。

4. **`无尽挑战_点击竞技` 是自循环节点**（`next` 里包含自己）。如果「竞技」按钮
   一直可见，它会反复命中并点击。干跑模式下无害；实跑时**留意别让它卡在循环里**。

## 下一步（取决于本次结果）

| 结果 | 下一步 |
|---|---|
| 三个节点都命中，分数 ≥0.90，OCR 能认对 | 识别层可用 → 值得移植 MaaPVZ 引擎（方案 A/B） |
| 模板匹配正常，OCR 全灭 | 先修 OCR（工作量可控，集中在 `OcrEngine.kt`） |
| 模板分数普遍偏低 | 检查模板缩放策略（`Recognizer.scale` vs MaaPVZ 的裁剪基准） |
| 完全没反应 | 检查截图链路（`ShizukuScreenCapturer`）与 assets 是否同步 |
